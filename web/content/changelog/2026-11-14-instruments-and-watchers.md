---
title: Each instrument has a watcher page, and its badge says whether new files will arrive
docs: https://datahub.arcadiascience.com/docs/manage-watchers#the-watcher-page
---

Everything about an instrument's watcher now lives on its own page, at **Instruments** → the instrument → **Watcher**. Select the status badge beside the instrument's name, or choose **Watcher** from its three-dot menu. The page has three tabs. **Activity** is the event log, now in plain words, with an event type filter, a date range that starts at the last 7 days, and **Show more**. **Health** shows the last 7 days: four counts, files uploaded per day, and a grid of every 30 minutes that shows missed heartbeats and restarts. **Settings** has the form for changing the watcher's settings, and the history of every change. Anyone signed in can read the page; admins can also change settings, restore an earlier version, and deregister the watcher. When another instrument's watcher runs on the same computer, the page says so, and an instrument that has had more than one watcher gets a switcher for the past ones. The **Edit watcher config** dialog is gone, and **View watcher** and **Edit watcher config** in the instrument menu are replaced by one **Watcher** item.

The instrument page is now built for the people who use the instrument. Its badge reads **Online**, **Restarting**, **Connecting**, **Offline**, **Pending**, or **Retired**, and hovering over it explains what that means for new files. A routine restart or automatic update shows **Restarting** instead of a red **Offline**. When the badge does read **Offline**, a notice says why: the watch folder is missing, the watcher isn't checking in, someone stopped it, or the instrument has no watcher. Admins get a button to fix it where one helps. An instrument in manual upload mode shows a note that files upload when someone requests them. The same badge appears in the instruments table, on Home, and in search.

On a run page, the **Upload** buttons follow the badge. They stay on while the instrument is **Restarting**, because requests wait for the watcher to come back, and when one is off, the reason shows beside it. There is a new **Upload all** button, and files that were found but not uploaded now read **Waiting to upload**, not **Pending**. If the instrument is **Offline** and the run still has files on the instrument PC, a notice says so.

For admins, **Settings → Watchers** now lists every watcher below the release form, with a pill that shows how many run the latest version, a marker for computers that run more than one watcher, and tabs for active and deregistered watchers. **Watchers** is no longer in the sidebar. Confirming a pending instrument opens a review of what its watcher was set up to do, and asks you to choose an instrument type, in one step.

Old links keep working. `/watchers` goes to **Settings → Watchers** for admins and to **Instruments** for members, and `/watchers/<id>` goes to the matching tab of the instrument's watcher page.

Instrument responses from the REST API (`GET /instruments` and `GET /instruments/:id`) and from the `list_instruments` and `get_instrument` tools now include `watcher`, `connection`, and a count of past watchers (`past_watcher_count` in REST, `pastWatcherCount` in MCP). The older fields are deprecated and still return the values they had: `watcherCount`, `watchersOnline`, `watchersOffline`, `hasDeregisteredWatcher`, `lastWatcherHeartbeatAt`, the `activeWatcher*` fields, the top-level `filePatterns`, and REST's `watcher_count`. On `global_search` results for an instrument, `watcherStatus` and `lastWatcherHeartbeatAt` are deprecated too. Move to the new fields before they are removed; a later entry will give the date.

You don't need to update the watcher. A watcher shows **Restarting** for a Windows restart from watcher 1.4.1 and for an automatic update from 1.4.2. Older watchers read **Offline** while they restart.
