<Audience>Lab operators and admins</Audience>

This walkthrough takes you from nothing to an uploading instrument: create an access token, install the watcher, register the instrument, get an admin to confirm it, then start watching. CLI flags, the full config schema, and Windows service setup each have their own page, linked where they come up.

<Callout type="warn">
Data Hub is self-hosted. The web app, PostgreSQL database, and AWS stack (S3 plus the processing Lambda) must already be running. If they aren’t, an engineer needs the [Deploy Data Hub](/docs/self-hosting) guide first.
</Callout>

## Before you start

You need:

- **The watch folder**: the folder your instrument saves its output to.
- **File patterns**: which files to upload, written as patterns such as `*.csv`, `*.xlsx`, or `*.tiff`.
- **[uv](https://docs.astral.sh/uv/getting-started/installation/)** installed on the instrument PC (it manages Python for you).

To make setup and maintenance easier, we recommend setting up remote access to the instrument PC via [Windows Remote Desktop](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access).

## 1. Create an access token

The watcher authenticates to Data Hub with a personal access token. Only admins can create tokens, so ask one if you aren’t an admin.

<Steps>

<Step>
In the Data Hub web app, go to **Settings → Access Tokens** and choose **Create token**.
</Step>

<Step>
Give the token a **Name** that identifies the instrument PC, for example `Plate Reader PC`.
</Step>

<Step>
Set **Expiration** to **No expiry**. An admin can still revoke the token at any time.
</Step>

<Step>
Under **Scopes**, choose the **Watcher** preset. It grants only what a watcher needs: registering, reporting runs, and uploading files.
</Step>

<Step>
Choose **Create token**, then copy the token. It starts with `dhub_` and is shown only once.
</Step>

</Steps>

![Create access token window with the name filled in and the Watcher scope preset selected](/images/token-create-dialog.webp)

Keep the token handy: you paste it into the setup wizard in step 3. For rotation, revocation, and the full scope list, see [Issue and revoke tokens](/docs/manage-tokens).

## 2. Install the watcher

On the instrument PC, install the watcher with `uv`. The `windows-service` extra adds `pywin32` so you can follow [Run as a Windows service](/docs/windows-service), which is the default on a lab PC:

```sh
uv tool install "data-hub-watcher[windows-service]"
```

On macOS or Linux, omit the extra:

```sh
uv tool install data-hub-watcher
```

[Install and update the watcher](/docs/install-the-watcher) has the full install, check, and update steps.

## 3. Run the setup wizard

Start the wizard with `data-hub-watcher init`. It prompts you for one thing at a time:

<Steps>

<Step>
Choose the environment. For a live lab, this is production.
</Step>

<Step>
Enter your Data Hub API URL, for example `https://datahub.your-domain.com/api/v1`.
</Step>

<Step>
Paste the token from step 1 when it asks for the API key. The wizard checks the key, then lists the instruments already registered.
</Step>

<Step>
Pick your instrument from the list, or choose **Register a new instrument** if it isn’t there.
</Step>

<Step>
For a new instrument, enter an ID and a display name. The ID is a short, lowercase, hyphenated name like `bio-rad-cfx96`. **It can’t be changed later.**
</Step>

<Step>
Enter the full path to the folder your instrument writes into.
</Step>

<Step>
List which files to upload, such as `*.pcrd,*.csv`. The watcher ignores files that don’t match.
</Step>

<Step>
Choose how files get grouped into runs. Pick the preset that matches how your instrument names its output, or write your own. The wizard previews a few matches so you can check the run IDs. For example, the default preset uses the filename prefix before the first underscore, so `RUN001_quant.csv` and `RUN001_melt.csv` both group into run `RUN001`.
</Step>

<Step>
Set the stability period: how many seconds a file must stay unchanged before the watcher treats it as finished. The default is 5. Raise it for instruments that write large files slowly.
</Step>

<Step>
Choose the upload mode. **Auto** uploads each file as soon as it’s stable. **Manual** waits until someone chooses **Upload** for the file in the web app.
</Step>

</Steps>

For run detection options, see [Configure run detection and uploads](/docs/configure-run-detection); [Watcher configuration](/docs/configuration-reference#run-detection) lists every preset.

The wizard then registers the watcher, saves the config to `~/.data-hub/config.yaml` (`C:\Users\your_username\.data-hub\config.yaml` on Windows), and sends it to Data Hub. When it reports that setup is complete, an admin confirms the instrument.

## 4. Confirm the instrument’s registration [#confirm-the-instruments-registration]

A pending instrument can’t upload to Data Hub until an admin confirms it from the web app. Until then its badge reads **Pending**, and its page shows a **Waiting for confirmation** card in place of the runs table. Members see one line saying the instrument is waiting for an admin.

<Steps>

<Step>
In the Data Hub web app, choose **Instruments → View all** in the sidebar.
</Step>

<Step>
Open the **Pending** tab and find your instrument. It shows an amber **Pending** badge.
</Step>

<Step>
Choose **Confirm…** on its row. A window shows what the watcher registered: the computer, the watch folder, the file patterns, how files become runs, and the upload mode. Check that it matches what you entered in the wizard. If it doesn’t, choose **Change settings first** to fix it.
</Step>

<Step>
Choose an **Instrument type**, which is required, then choose **Confirm instrument**. The instrument moves to the **Active** tab.
</Step>

</Steps>

![Instruments page on the Pending tab, with a pending instrument showing an amber Pending badge and a Confirm button](/images/instruments-pending.webp)

![The Confirm window, with the instrument’s ID, where the watcher registered from, its watch folder, file patterns, how files become runs, and the instrument type to choose](/images/instrument-confirm-dialog.webp)

The instrument’s badge reads **Connecting** until the watcher service you start in step 5 checks in, and then **Online**. If the watcher hasn’t checked in 15 minutes after you confirm, the badge reads **Offline** with the notice “The watcher never checked in”. That’s expected if you haven’t started the service yet, and the badge turns **Online** at the first check-in.

Open the instrument’s page and check the watch folder and file patterns shown under its name. They should match what you entered in the wizard. Files outside that folder, or with names that don’t match a pattern, won’t reach Data Hub.

Admins can change an instrument’s type later: open the three-dot menu, choose **Edit details**, and pick a supported type. What each type produces is in [Instrument data preprocessing](/docs/instrument-preprocessing).

<Callout type="info">
Adding a new processor takes code changes; see [Adding a new instrument](https://github.com/Arcadia-Science/data-hub/blob/production/docs/developer/lambda.md#adding-a-new-instrument) in the developer docs.
</Callout>

[Manage instruments](/docs/manage-instruments) covers confirming and editing instruments and reading an instrument’s page.

## 5. Start the watcher service [#start-the-watcher-service]

First, preview what the watcher will do without starting it:

```sh
data-hub-watcher watch --dry-run
```

The dry run checks the config, checks that Data Hub is reachable and the instrument is active, and lists the files it would upload.

When it looks right, install and start the watcher as a Windows service. Run these from an **Administrator** terminal:

```sh
data-hub-watcher service install
data-hub-watcher service start
```

The service starts when the PC starts, keeps running after you sign out of Windows, and updates itself. [Run as a Windows service](/docs/windows-service) covers stopping and restarting it, and where it writes logs.

On macOS or Linux, run the watcher in the foreground instead:

```sh
data-hub-watcher watch
```

The watcher finds new files, groups them into runs, uploads them in auto mode, and checks in with Data Hub every 60 seconds. Runs appear in the web app as the watcher reports them, and their files follow as they upload.

## What you get once it’s running [#what-you-get-once-it-is-running]

- Raw files upload to cloud storage
- The instrument’s runs and files appear in the web app
- The watcher service starts again whenever the PC restarts
- The watcher’s activity, health, and settings appear on the instrument’s **Watcher** page, and the instrument’s badge shows whether new files can arrive
- People who subscribe to the instrument can get notifications about new runs in the app and in Slack
