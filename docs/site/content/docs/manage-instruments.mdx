<Audience>Administrators</Audience>

When a lab operator registers an instrument from the watcher, it appears as `pending` and can’t upload until you confirm it. [Set up an instrument](/docs/set-up-an-instrument) covers the operator’s side. [Retire an instrument](/docs/retire-an-instrument) covers retiring and reactivating.

## Instrument states [#instrument-states]

The **Instruments** page has tabs for active, pending, and retired instruments.

| Status | UI label | Meaning |
| --- | --- | --- |
| `pending` | Pending | Registered but not confirmed. Watchers can’t upload. |
| `active` | Active | Confirmed and accepting uploads. |
| `inactive` | Retired | Taken out of service. No new uploads, and past runs stay browsable. |

Each instrument also has a status badge that says whether its new files can arrive. See [Read an instrument’s page](#view-instrument-health).

![Instruments page with Active, Pending, and Retired tabs](/images/instruments-table.webp)

## Confirm a pending instrument [#confirm-a-pending-instrument]

Confirming opens a review of what the watcher was set up to do, so you can check it before files start to flow.

<Steps>

<Step>
Open the Data Hub web app and go to **Instruments**.
</Step>

<Step>
Open the **Pending** tab (or find the amber **Pending** badge), and choose **Confirm…** on the instrument’s row. You can also open the pending instrument’s page, which has a **Waiting for confirmation** card with the same button.
</Step>

<Step>
Read the review. It shows the instrument’s ID, which can’t be changed later, and what the watcher registered:

- **Registered from**: the computer, and the name of the token the watcher registered with
- **Watch folder**: the folder the watcher reads from
- **File patterns**: which files the watcher uploads
- **How files become runs**: a plain name for the preset, with one example from a recent or sample file name
- **Upload mode**: **Automatic** or **Manual**

</Step>

<Step>
Choose an **Instrument type**. It’s required, because it decides how files are processed and which details appear on run pages.
</Step>

<Step>
Choose **Confirm instrument**. The instrument becomes active and its type is saved in one step.
</Step>

</Steps>

![Instruments page on the Pending tab, with a pending instrument showing an amber Pending badge and a Confirm button](/images/instruments-pending.webp)

![The Confirm window, with the instrument’s ID, where the watcher registered from, its watch folder, file patterns, how files become runs, and the instrument type to choose](/images/instrument-confirm-dialog.webp)

If something in the review looks wrong, choose **Change settings first**. It opens the watcher’s **Settings** tab, which works for a pending instrument, so you can fix the folder or patterns before you confirm. See [Change a watcher’s settings](/docs/manage-watchers#change-a-watchers-config).

After you confirm, the operator starts the watcher service on the PC (step 5 of [Set up an instrument](/docs/set-up-an-instrument#start-the-watcher-service)). The badge goes from **Connecting** to **Online** once the watcher checks in. If the watcher hasn’t checked in 15 minutes after you confirm, the badge turns **Offline**, and its notice says the watcher never checked in.

Members who open a pending instrument’s page see one line instead of the card: “This instrument is waiting for an admin to confirm it. Runs will appear here after that.”

A signed-in user has to be an admin to confirm an instrument. Through the API, confirming is `PATCH /api/v1/instruments/your_instrument_id` with `status` and `instrument_type` in the same request. A script that uses a token needs the `instruments:write` scope instead of the admin role. See the [generated API docs](/docs/api).

## Read an instrument’s page [#view-instrument-health]

The top of each instrument page shows what you need to tell whether its files will reach Data Hub:

- **Status badge**: next to the instrument name, it reads **Online**, **Restarting**, **Connecting**, **Offline**, **Pending**, or **Retired**. Hover over it for a short explanation. Select it to open the watcher’s page, the only place that shows the watcher’s hostname and version.
- **Watch folder**: the folder the watcher reads from. Hover over it for a reminder that files saved anywhere else don’t appear, and select it to copy the path.
- **File patterns**: the patterns the watcher uploads, such as `*.csv`.
- **Manual upload note**: an instrument in manual upload mode shows “Files upload when someone requests them” beside the patterns, whatever the badge says.

The badge follows the instrument’s one watcher, which checks in once a minute. After a restart, a watcher can take up to a minute to show as online. The rules are in [Instrument status](/docs/concepts#instrument-status).

When the badge reads **Offline**, a notice between the header and the runs table says why. The actions it offers depend on the reason:

- **The watch folder is missing**: **See details** opens the watcher’s **Activity** tab. Admins also get **Change folder**, which opens the watcher’s settings form with the **Watch folder** field selected.
- **The watcher isn’t checking in, or someone stopped it**: **See details** opens the watcher’s **Activity** tab.
- **The instrument has no watcher, or its watcher was deregistered**: there’s no current watcher to look at. Admins get **Connect a watcher**, which opens [Set up an instrument](/docs/set-up-an-instrument), and members get no action.

[Check that new files will arrive](/docs/browse-runs#check-files-will-arrive) describes the notices from the scientist’s side, with a table of every notice.

![Instrument page with a red Offline badge and a notice that the watcher can’t find its watch folder, with Change folder and See details](/images/instrument-offline-notice.webp)

Files saved anywhere other than the watch folder, such as a shared network drive, don’t appear in Data Hub. Neither do files whose names don’t match a pattern.

Admins can change the folder and patterns on the watcher’s **Settings** tab; see [Change a watcher’s settings](/docs/manage-watchers#change-a-watchers-config). You can also change them on the PC with `data-hub-watcher config edit`; see [Watcher configuration](/docs/configuration-reference).

Data Hub judges a watcher’s health from its heartbeats, the check-ins it sends once a minute. See [Manage the watcher fleet](/docs/manage-watchers).

## Edit an instrument [#edit-an-instrument]

The three-dot menu on an instrument page and the row menu on the **Instruments** table hold the admin actions:

- **Edit details**: change the **Display name** and the **Instrument type**
- **Watcher**: open the instrument’s watcher page, where its settings are
- **Retire** or **Reactivate**: see [Retire an instrument](/docs/retire-an-instrument)

Members see no menu on the instrument page. They reach the watcher page through the status badge.

![Edit instrument window with the display name and instrument type fields](/images/instrument-edit-dialog.webp)

The instrument type decides which processor reads the instrument’s files, including DishCam and Aunty. See [Instrument data preprocessing](/docs/instrument-preprocessing). The instrument ID never changes, because Data Hub uses it in the storage path of every file.
