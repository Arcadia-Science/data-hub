<Audience>Administrators</Audience>

When a lab operator registers an instrument from the watcher, it appears as `pending` and cannot upload until you confirm it. Operator-side setup is in [Set up an instrument](/docs/set-up-an-instrument). Retiring and reactivating are in [Retire an instrument](/docs/retire-an-instrument).

## Instrument states [#instrument-states]

The **Instruments** page has tabs for active, pending, and retired instruments.

| Status | UI label | Meaning |
| --- | --- | --- |
| `pending` | Pending | Registered but not confirmed. Watchers cannot upload. |
| `active` | Active | Confirmed and accepting uploads. |
| `inactive` | Retired | Deactivated; no new uploads. Historical runs stay browsable. |

Each instrument also has a status badge, which says whether its new files can arrive; see [Read an instrument’s page](#view-instrument-health).

![Instruments page with Active, Pending, and Retired tabs](/images/instruments-table.webp)

## Confirm a pending instrument [#confirm-a-pending-instrument]

Confirming opens a review of what the watcher was set up to do, so you can check it before files start to flow.

<Steps>

<Step>
Open the Data Hub web app and go to **Instruments**.
</Step>

<Step>
Open the **Pending** tab (or find the amber **Pending** badge), and choose **Confirm…** on the instrument’s row. You can also open the pending instrument’s page, which has a **Waiting for confirmation** card with the same button.
</Step>

<Step>
Read the review. It shows the instrument’s ID, which can’t be changed later, and what the watcher registered: the computer and the name of the token it registered with, the watch folder, the file patterns, how files become runs (a plain name for the preset, with one example from a recent or sample file name), and the upload mode.
</Step>

<Step>
Choose an **Instrument type**. It’s required, because it decides how files are processed and which details appear on run pages.
</Step>

<Step>
Choose **Confirm instrument**. The instrument becomes active and its type is saved in one step.
</Step>

</Steps>

![Instruments page on the Pending tab, with a pending instrument showing an amber Pending badge and a Confirm button](/images/instruments-pending.webp)

![The Confirm window, with the instrument’s ID, where the watcher registered from, its watch folder, file patterns, how files become runs, and the instrument type to choose](/images/instrument-confirm-dialog.webp)

If something in the review looks wrong, choose **Change settings first**. It opens the watcher’s **Settings** tab, which works for a pending instrument, so you can fix the folder or patterns before you confirm. See [Change a watcher’s settings](/docs/manage-watchers#change-a-watchers-config). After you confirm, the operator starts the watcher service on the PC (step 5 of [Set up an instrument](/docs/set-up-an-instrument#start-the-watcher-service)), and the badge goes from **Connecting** to **Online** once the watcher checks in.

Members who open a pending instrument’s page see one line instead of the card: “This instrument is waiting for an admin to confirm it. Runs will appear here after that.”

Confirming is admin-only for signed-in users. Under the hood it is `PATCH /api/v1/instruments/:id` with `status` and `instrument_type` together. Token automation uses the `instruments:write` scope instead. See the [generated API docs](/docs/api).

## Read an instrument’s page [#view-instrument-health]

The top of each instrument page shows what you need to tell whether its files will reach Data Hub:

- **Status badge**: **Online**, **Restarting**, **Connecting**, **Offline**, **Pending**, or **Retired**, next to the instrument name. It follows the instrument’s one watcher, which checks in once a minute, so a watcher that was just restarted can take up to a minute to show as online. Hover over the badge for a short explanation, or select it to open the watcher’s page. Hostname and version are only on that page. The rules are in [Instrument status](/docs/concepts#instrument-status).
- **Watched folder**: the folder the watcher reads from. Hover over it for a reminder that files saved anywhere else don’t appear, and select it to copy the path.
- **File patterns**: the patterns the watcher uploads, such as `*.csv`.
- **A note for manual upload mode**: “Files upload when someone requests them,” beside the patterns, whatever the badge says.

When the badge reads **Offline**, a notice between the header and the runs table says why: the folder is missing, the watcher isn’t checking in, someone stopped it, or the instrument has no watcher. When the folder is missing, the watcher isn’t checking in, or someone stopped it, the notice offers **See details**, which opens the watcher’s **Activity** tab. For a missing folder, admins also get **Change folder**, which opens the watcher’s settings form with the **Watch folder** field selected. When the instrument has no watcher, or its watcher was deregistered, there is nothing current to look at: admins get **Connect a watcher**, which opens [Set up an instrument](/docs/set-up-an-instrument), and members get no action. The notices are described from the scientist’s side in [Check that new files will arrive](/docs/browse-runs#check-files-will-arrive).

![Instrument page with a red Offline badge and a notice that the watcher can’t find its watch folder, with Change folder and See details](/images/instrument-offline-notice.webp)

Files saved anywhere other than the watched folder, such as a shared network drive, don’t appear in Data Hub. Neither do files whose names don’t match a pattern. Admins can change the folder and patterns on the watcher’s **Settings** tab (watcher 1.4.0 and later); see [Change a watcher’s settings](/docs/manage-watchers#change-a-watchers-config). You can also change them on the PC with `data-hub-watcher config edit`; see [Watcher configuration](/docs/configuration-reference).

Watcher health comes from heartbeats; see [Manage the watcher fleet](/docs/manage-watchers).

## Edit an instrument [#edit-an-instrument]

The three-dot menu on an instrument page, and the row menu on the instruments table, hold the admin actions. Members see no menu on the instrument page, and reach the watcher page through the status badge.

- **Edit details**: change the **Display name** and the **Instrument type**
- **Watcher**: open the instrument’s watcher page, where its settings are
- **Retire** or **Reactivate**: see [Retire an instrument](/docs/retire-an-instrument)

![Edit instrument window with the display name and instrument type fields](/images/instrument-edit-dialog.webp)

The instrument type decides which processor reads the instrument’s files, including DishCam and Aunty; see [Instrument data preprocessing](/docs/instrument-preprocessing). The instrument ID never changes, because it is the storage key prefix.
