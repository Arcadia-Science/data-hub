## Interactive setup notes

`init` and `config edit` ask for values in the terminal. Those prompts aren’t CLI flags, so they don’t appear in the catalog.

API keys must start with `dhub_`. The watcher removes zero-width and non-breaking space characters, which some Windows clipboards add to a pasted key. See [Install and update the watcher → Configure](/docs/install-the-watcher#configure).

## Upload examples

Upload files once, without running the watcher:

```sh
data-hub-watcher upload --file /path/to/file.csv --run-id RUN001
data-hub-watcher upload
data-hub-watcher upload --dry-run
```

Pass both `--file` and `--run-id` to upload one file. Leave out both to work through the server’s upload queue, the way a manual-mode watcher does.

## Switching environments

`config set-environment` can take `--api-base-url`, `--api-key`, `--show-key`, and `--no-register`, and so can `config edit` when the environment changes. Switching to a preview deployment needs `--api-base-url` the first time. See [Watcher configuration → Switching environments](/docs/configuration-reference#switching-environments).

## Windows service notes

`service` commands need Windows and the `windows-service` install extra. Use `--env-path` on `service install` and `service reinstall` when the service should load a `.env` file other than the default one. [Run as a Windows service](/docs/windows-service) has the full details.

## Self-update examples

```sh
data-hub-watcher self-update
data-hub-watcher self-update --check
data-hub-watcher self-update --force
```

How the upgrade works depends on how you installed the watcher. See [Install and update the watcher → Manual update](/docs/install-the-watcher#manual-update-self-update).
