<Audience>Administrators</Audience>

Retire an instrument when it’s taken out of service for good or for a long time. Retiring sets its status to `inactive`, shown as **Retired**, and stops new uploads. The instrument leaves the sidebar and the home page’s list of instruments. Nothing is deleted from storage, and you can reactivate it later.

## What retirement does

When you retire an instrument:

- Its status becomes `inactive`, shown as **Retired**. Data Hub records who retired it and when, and the instrument page shows both.
- It stops accepting new runs and watchers.
- Its badge reads **Retired**, and the **Upload** buttons on its run pages are turned off.
- All existing runs and files stay browsable.
- Its watcher is deregistered in the same request, so it stops checking in. The watcher stays on the instrument’s watcher page as a past watcher.

An instrument’s ID never changes. To stop using an instrument that has already produced data, retire it instead of trying to rename or delete it.

## Retire from the web app

<Steps>

<Step>
Open the instrument’s page.
</Step>

<Step>
Open the three-dot menu, which only admins see, and choose **Retire**. The row menu on **Instruments** has the same item.
</Step>

<Step>
Read the window that opens, then choose **Retire instrument**. The window says how many runs are kept and that nothing is deleted from storage. When the instrument has a watcher, it also says the watcher will be deregistered so it stops checking in.
</Step>

</Steps>

![Retire instrument window explaining that the instrument’s runs and files are kept and that its watcher will be deregistered](/images/instrument-retire-dialog.webp)

The instrument moves to the **Retired** tab on **Instruments**.

## Reactivate

From a retired instrument’s page, open the three-dot menu and choose **Reactivate**. The row menu on the **Retired** tab has the same item. The status returns to `active`, and the instrument appears in the sidebar and on the home page again.

After you reactivate, an operator has to register a watcher again by running `data-hub-watcher init` on the instrument PC. The watcher that was deregistered at retirement stays disconnected. Until a new one registers, the badge reads **Offline** and a notice says the instrument isn’t connected to a watcher. Admins can choose **Connect a watcher** to open [Set up an instrument](/docs/set-up-an-instrument).

## Via the API

```sh
# Retire
curl -X PATCH https://datahub.example.com/api/v1/instruments/bio-rad-cfx96 \
  -H "Authorization: Bearer dhub_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"status":"inactive"}'

# Reactivate
curl -X PATCH https://datahub.example.com/api/v1/instruments/bio-rad-cfx96 \
  -H "Authorization: Bearer dhub_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"status":"active"}'
```

Signed-in users need the admin role. Scripts that use a token need the `instruments:write` scope.
