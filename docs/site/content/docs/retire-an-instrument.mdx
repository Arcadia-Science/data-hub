<Audience>Administrators</Audience>

Retire an instrument when it is decommissioned or out of service for a long stretch. Retirement sets status to `inactive` (shown as **Retired**), removes it from the sidebar and dashboard lists of live instruments, and stops new uploads. Nothing is deleted from storage; you can reactivate later.

## What retirement does

When you retire an instrument:

- Status becomes `inactive` (UI: **Retired**), with `retiredAt` / `retiredBy` audit fields
- It stops accepting new runs and watchers
- Its badge reads **Retired**, and its Upload buttons on run pages are turned off
- All existing runs and files stay browsable
- Its watcher is deregistered in the same request so it stops checking in. The watcher stays on the instrument’s watcher page as a past watcher

Instrument IDs stay permanent. Retire rather than trying to rename or delete an instrument that has already produced data.

## Retire from the web app

<Steps>

<Step>
Open the instrument’s page.
</Step>

<Step>
Open the three-dot menu, which only admins see, and choose **Retire**. The row menu on **Instruments** has the same item.
</Step>

<Step>
Confirm in the dialog. It lists how many runs are kept, says nothing is deleted from storage, and, when the instrument has a watcher, says its watcher will be deregistered so it stops checking in.
</Step>

</Steps>

![Retire instrument window explaining that the instrument’s runs and files are kept and that its watcher will be deregistered](/images/instrument-retire-dialog.webp)

The instrument moves to the **Retired** tab on **Instruments**.

## Reactivate

From a retired instrument’s page, open the three-dot menu and choose **Reactivate**. The row menu on the **Retired** tab has the same item. Status returns to `active` and the instrument reappears in the sidebar and dashboard.

The watcher deregistered at retirement does **not** reconnect automatically. An operator must re-register it (usually `data-hub-watcher init` on the instrument PC) after reactivation. Until then the instrument’s badge reads **Offline**, with a notice that it isn’t connected to a watcher, and admins can follow **Connect a watcher** to [Set up an instrument](/docs/set-up-an-instrument).

## Via the API

```sh
# Retire
curl -X PATCH https://datahub.example.com/api/v1/instruments/bio-rad-cfx96 \
  -H "Authorization: Bearer dhub_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"status":"inactive"}'

# Reactivate
curl -X PATCH https://datahub.example.com/api/v1/instruments/bio-rad-cfx96 \
  -H "Authorization: Bearer dhub_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"status":"active"}'
```

Session callers need the admin role; bearer tokens need `instruments:write`.
